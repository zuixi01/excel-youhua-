# ADR-0001：采用内部 Open XML SDK 渲染器

- 状态：已接受
- 日期：2026-08-28

## 决策

生产渲染边界保持为 `ExcelRenderer` 协议，当前实现使用固定版本 `DocumentFormat.OpenXml 3.5.1` 的内部 .NET 渲染器，不复制或 fork `xlsx-review` 源码。

## 原因

阶段 0 评估后，平台需要确定性的 manifest、输入哈希校验、逐操作结果、宏部件原样保留、Table/筛选/数据验证/命名区域更新，以及明确的失败封锁。现有候选项目不能同时提供这些契约；直接 fork 会引入更大的未验证表面和维护责任。内部实现只消费稳定 JSON manifest，后续仍可在不改变比较引擎和 API 的情况下替换。

## 约束与验证责任

- 不执行公式、宏或外部连接。
- 不安全或不支持的结构进入人工审核，不静默降级。
- 依赖由 `packages.lock.json` 锁定，许可证和漏洞由 CI 门禁检查。
- 合约测试必须覆盖输入哈希、批注/颜色、插列、公式引用、Table、筛选、数据验证、命名区域、公式字符串字面量、逐操作结果和 VBA 部件哈希。
- Linux 自包含二进制须在发布镜像内冒烟；输出须经 Open XML 回读和 LibreOffice 打开/另存验证。

## 后果


团队承担渲染器回归与兼容性责任；新增 Open XML 结构支持前必须先补 Golden/合约测试。若未来替换为外部实现，只能在相同 manifest、结果协议和安全门禁下进行。
