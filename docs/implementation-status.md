## 当前实现

已完成的本地实现包括：严格且版本化的规则模型、JSON/CSV/受管 HTTP 标准数据接入、不可变标准快照、工作簿安全预检、表头映射、单/联合主键匹配、类型化比较、字段及跨字段校验、受控修复、JSON/HTML/Excel 报告、FastAPI/Web、PostgreSQL/Redis/RQ/MinIO 适配器、租户隔离、审计与保留策略。Web 的任务、规则与下载请求统一支持 Bearer 鉴权，令牌只保存在当前浏览器会话，文件通过鉴权请求下载。生产 Compose 为受管 HTTP 连接注册表和秘密目录提供只读挂载；连接配置严格拒绝未知字段和重复键，密钥不进入规则或镜像。敏感字段（含解析失败的主键）在 JSON、JSONL、HTML、Excel 内嵌报告/批注、公开 manifest、任务状态和数据库审计中统一掩码；只有已授权的结果业务单元格保留实际写入值，临时私有 manifest 在所有终止路径删除。每项自动修复的 Excel 批注现固定包含脱敏原值、脱敏标准值和实际修复规则 ID；操作级数据库审计同时保留修复规则与差异比较规则，公开 manifest 只保留规则来源并再次移除批注业务值。

核心精度入口现统一拒绝会产生静默选择或值丢失的标准数据：规范字段名、展示名和别名按 NFKC/空白规则映射，同一字段的冲突表示、JSON 重复对象键、CSV 重复字段名、HTTP 非严格 JSON 均在快照前失败。上传 JSON、内联 JSON 和受管 HTTP 响应中的小数 token 直接解析为 Decimal，不先经过二进制浮点舍入；顶层 decimal 字段与嵌套 JSON 数字在不可变快照中均保持精确数值类型，不退化为字符串。无 Decimal 的常见快照记录仍使用原生快速编码路径；规则文档与普通任务参数保持原有类型契约。不同物理表头即使文字不同，只要映射到同一规范字段也按重复表头处理，不会由后列覆盖前列。标准端和 Excel 端的长度、正则、枚举、唯一性均基于相同的规范化值语义；规则发布会拒绝负/非有限容差、矛盾范围、类型不兼容选项、歧义枚举和违反自身校验的静态默认值，也会拒绝重复工作表别名、空白字段标题、非法规范字段标识、无效集合分隔符，以及经标准化或正则处理后永远无法命中的值别名/枚举。字符串长度/正则、日期时间精度和日期解析格式都按字段类型做发布期校验，不会再对数值的字符串表示误判或接受运行时无效选项。内置跨字段校验器使用精确参数契约，拒绝缺失/拼错参数、无效条件值、类型不兼容的日期字段和重复规则 ID，避免规则被静默跳过。主键字段必须使用确定性的精确比较、禁止模糊类型和公式模式；Excel 公式主键会被排除出匹配索引、产生明确差异并转人工审核。`formula_mode=formula` 对字符串、数值和日期等字段都按公式文本对称比较，不执行公式；标准字段省略仍保持“无权威值”语义。缺失记录中的公式只有与受信任 `formula_template` 在目标行展开后精确一致才允许自动追加，否则转人工审核且不生成结果 Excel。缺失公式列同样要求公式文本模式且不能与静态默认值混用；标准源若提供公式，必须与模板按目标物理行展开后的文本精确一致，否则任务转人工审核。空主键的 `report_invalid`、`skip_row`、`use_row_number` 在标准校验和比较引擎中使用同一语义：跳过行不再被其他字段误阻断，行号回退仍严格校验非主键字段。显式 `row_number` 主键的伪字段会在上传标准规范化时保留，且只有标准行号等于实际下一物理行时才允许自动追加，避免把记录写入错误行；多个缺失记录使用连续且互不覆盖的物理行。显式行号只接受 Excel 范围内的正整数或 CSV 精确整数字符串，布尔、小数、带空白文本和越界值不会再被 `int()` 静默截断或转换。Excel 侧未格式化的日期序列依据工作簿保存的 1900/1904 日期系统解析，日期主键、普通日期和带时间小数均使用同一 epoch；标准源数值不会被误当作 Excel 序列。日期与日期时间修复写回也读取同一工作簿 epoch，并处理 1900 系统的虚构闰日边界；1900-01-01、1904 日期和带时间小数均锁定原始序列与回读值。类型化修复使用与比较相同的规范值写入：布尔、枚举、百分比 Decimal、日期时间时区、集合和 JSON 均保持 Excel 类型/稳定表示，而报告继续保留标准原始值用于审计。任意精度数值仍可参与精确比较；只有自动修复写回会受 Excel 数值单元格 15 位有效数字和有限指数范围约束，无法安全往返的大整数/高精度小数会生成明确差异、转人工审核且不产生结果 Excel，绝不静默舍入或退化为文本。Decimal 非有限值及大精度量化有确定性边界；标准记录省略可选字段不会触发自动清空，只有显式空值才进入已授权覆盖路径。

工作表别名解析同样不允许静默任选：一个规则若同时匹配规范表名与一个或多个别名工作表，任务生成 `AMBIGUOUS_SHEET` 并进入人工审核，不执行记录匹配或渲染；受管多表标准响应若同时用 sheet id 与 sheet name 指向同一规则，则在快照前以 `STANDARD_DATA_INVALID` 拒绝。开发降级渲染器与生产 manifest 均使用已经确认的物理工作表名。安全预检与比较引擎共享同一自动表头定位结果，因此允许公式不会因前导说明行被误拦截，实际定位行上的合并表头也不会漏检。显式数据起始行必须晚于表头；自动定位后发生重叠会进入人工审核。工作表最大数据行数在有界表头扫描后按实际首数据行精确复核，普通与磁盘溢写模式既不把前导说明区误计为数据，也不放过超限记录。

配置文档在进入 Pydantic 前也执行严格装载：规则 JSON/YAML、规则草稿/已发布版本、连接注册表、API 内联标准 JSON 和任务参数均拒绝重复键及非有限 JSON 数字。受管 HTTP 路径必须是规范化的 origin-relative path，拒绝点段、反斜杠、重复斜杠、查询/片段、非法 UTF-8 以及单层或多层百分号编码绕过；静态、任务映射和分页参数不得重名覆盖，JSONPath 在规则发布时验证为运行期实际支持的简单对象路径。上传型标准源携带任何不会生效的 HTTP 配置也会直接失败。

.NET Renderer 当前覆盖标色、批注、插列、类型化写值、追加记录、报告/隐藏元数据工作表、样式去重、Table/AutoFilter/DataValidation/ConditionalFormatting/DefinedName/合并区域和简单 A1 公式引用维护。缺失公式列使用比较阶段解析出的实际表头行、显式/推导的数据起始行和非空目标数据行清单，避免在前导说明行、空洞行或错误的默认表头行生成公式；新列验证范围也从真实数据起始行开始。生产与开发渲染路径共用同一差异主颜色优先级：行级多余/缺失低于值不一致，值不一致低于无效值，歧义/重复最高；低优先级整行标色不会覆盖高优先级单元格，同一单元格的多条问题说明合并进入批注。Renderer manifest 在接触输出文件前严格校验操作列表、操作专属字段、A1/XFD/1048576 坐标、追加值所属行、字段类型及值类型、Excel 安全数值精度/范围、数值/列表验证、公式占位符、哈希和保留工作表名；无效或声明后不会生效的字段统一返回 `MANIFEST_OR_STRUCTURE_INVALID`，不再静默忽略。命令行层同样拒绝未知/重复/缺失参数、输入输出同路径和扩展名不一致，所有失败均返回结构化 JSON；Python 适配器保留参数、manifest、输出验证、不支持功能和通用渲染错误的原始类别，不再统一降级为 `RENDER_FAILED`。追加行会扩展相邻 Table/AutoFilter 和数据验证范围，单格 `sqref` 与显式范围使用相同扩展语义；内部超链接、局部命名区域、筛选列索引、排序引用，以及其他工作表中引用目标表的条件格式/数据验证公式均有插列维护。图表/绘图、透视表、外部链接以及复杂/共享/数组公式（含条件格式和数据验证中的复杂公式）在插列时明确返回 `UNSUPPORTED_FEATURE`，不会静默修改。VML 预检以流式 XML 结构区分纯批注和任意旧式控件/宏，非 `Note` 形状在渲染前转人工审核；固定宏包在实际标色与批注后验证 VBA 项目及签名部件逐字节保持。Renderer 还提供结构化 `--version` 自检，API 就绪探针会实际执行并校验其身份与语义版本。

固定 Golden 语料目前为 19 个工作簿：15 个核心表头/记录场景，外加联合主键与完整类型、结构化多工作表、合并表头人工审核，以及 10,000×20 大文件报告模式。大文件输入和 10,000 条标准 JSONL 快照均锁定 SHA，并强制工作簿与标准记录走磁盘后备序列及 Polars 分区连接。Golden 测试校验输入 SHA、完整差异计数/语义投影以及关键渲染结构；Renderer 合约另覆盖公式引用、Table、筛选、验证、命名区域、内部超链接、宏部件字节保持和不安全插列拒绝。字段统计按 `sheet_id.field` 隔离同名字段，值差异率与校验错误率分别使用该表匹配记录和实际验证记录作分母，内存/磁盘报告路径使用相同口径并包含零差异字段。
